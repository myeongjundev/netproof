# NetProof v1.0.0 릴리스 노트 (2026-10-24)

네트워크 구성에 대한 AI의 답이나 내 예상을 계산으로 확인하고, 경로·규칙의 근거를 보며 배우는 보안 네트워크 학생용 실습실. 이번 판은 최종 제출본이며, ALEPH 방어전에서 배운 것을 옮겼다([설계](v1-final-design.md)).

- 공개 주소: https://netproof-vert.vercel.app (로그인 없이 학습·실습·침해 가정·판정·정책 검증)
- 소스: https://github.com/myeongjundev/netproof · 태그 `v1.0.0`
- 버전: 웹 앱 1.0.0 · 계산 엔진 0.2.0(판정 의미는 1차 점검 이후 바뀌지 않음)
- 변경 기록: [CHANGELOG.md](../CHANGELOG.md)

## 확인하는 방법 (3단계)

1. 공개 주소 홈에서 "침해 가정 실습 열기"를 눌러 장면 1로 간다.
2. "확인하기" → 피해 범위 `처음 구성 3곳 · 서비스 15개`.
3. 구성 고치기에서 FW em1 규칙을 TCP 10.0.10.10 → 10.0.20.10:3306으로 바꾸고 "고친 구성 확인하기" → `지금 1곳 · 서비스 1개`. 아래 "수복 기록"에서 처음 15개 가운데 막힌 수와 바꾼 구성을 보고 `.md`로 내려받는다.

## 근거 구분 — 무엇을 확인했고 무엇을 확인하지 않았나

방어전의 원칙대로 근거를 섞지 않는다.

| 근거 | 확인한 것 | 한계 |
| --- | --- | --- |
| 자동 시험(직접 실행) | 엔진 508 passed·2 xfailed, 서버 252 passed·1 skipped, 웹 823 passed(종료 0) | 합성 입력과 저장된 엔진 응답 |
| 실제 브라우저 | 로컬 임시 SQLite와 공개 사이트에서 장면별 흐름(확인 → 고치기 → 다시 확인 → 수복 기록), 320·375·1280px | AI가 확인했다. 사람 수동 QA(F·G·H)는 아직이다 |
| 공개 배포 | 공개 JS·CSS SHA256이 로컬 빌드와 같음(병합 뒤 확인) | — |
| 실제 장비 | **대조하지 않았다.** 방화벽은 제한된 상태 추적 모델이다 | pfSense 실제 기준 사례는 후속(팀 실습망 캡처 필요) |
| 사용자 확인 | **다른 사용자 확인 없음.** AI가 학생 입장으로 써 본 점검만 있다 | AI는 사이트를 만든 쪽이라 실제 첫 사용자와 다르다 |

## 알려진 한계

- "닿음"은 방화벽과 경로가 막지 않아 연결을 시작할 수 있다는 뜻일 뿐이다. 서비스가 열려 있는지·취약한지는 계산하지 않는다.
- 검사한 서비스와 호스트 쌍만 계산한다. 검사하지 않은 통신은 알 수 없다.
- IPv6·NAT(포트포워딩)·동적 라우팅·VLAN·별칭이 판정에 필요하면 "판정 불가"로 멈춘다.
- ZTNA는 "필요한 앱만 연다"는 네트워크 부분만 계산한다. 사용자·기기 확인은 계산하지 않는다. XDR의 탐지·격리는 NetProof의 범위가 아니다.
- 운영 DB의 저장 사례 재판정은 비밀번호 미확보로 보류 중이다.
