## 1. 어려운 합성 사례 7개

### 순서 (순서가 중요하다)

1. 아래 `[상황]` 하나를 골라 Workbench에 **프롬프트 1**로 JSON 초안을 받는다.
2. `cases/synthetic-0N-<짧은이름>.json`으로 저장하고, 초안이 `[상황]`과 같은지 한 줄씩 대조한다(주소·ACL 방향·규칙 순서).
3. **엔진을 돌리기 전에** `expect`를 손으로 채운다. 종이에 패킷을 한 칸씩 따라가며 가는 길과 돌아오는 길을 모두 본다.
   `result`(PASS/DENY/UNSUPPORTED), `device`, `step`(send·acl_in·route·acl_out·deliver), `rule_seq`(ACL 규칙 번호. 규칙이 아닌 이유로 막히거나 암묵적 deny면 null).
   PASS나 UNSUPPORTED면 `result`만 적어도 된다.
4. `engine` 폴더에서 테스트를 돌린다.

   ```powershell
   ..\.venv\Scripts\python -m pytest tests/test_cases.py -q
   ```

5. 실패하면 셋 중 누가 틀렸는지 가린다. **어느 쪽이든 결과다.**
   - 내 손계산이 틀렸다 → 어디서 헷갈렸는지 한 줄 적고 고친다(발표 재료: "나도 틀린다").
   - JSON 초안이 `[상황]`과 다르다 → AI가 옮기다 틀린 것. `disagreement-log.md`에 적는다.
   - 엔진이 `docs/semantics.md`와 다르게 판정했다 → 엔진 버그. 고치기 전에 Claude에게 검토를 부탁해도 된다.

### 프롬프트 1 — JSON 초안

`{ }`만 바꾼다. `[형식 예시]`에는 `cases/synthetic-02-missing-return-route.json` 내용을 통째로 붙인다.

```text
아래 [형식 예시]와 똑같은 JSON 형식으로 새 사례를 하나 만들어 주세요.

- [상황]에 적힌 장비·설정·통신만 옮기세요. 없는 장비·경로·규칙을 더하지 마세요.
- ACL은 "acls"에 {"이름": ["access-list ... 한 줄", ...]}로 적고, 붙인 인터페이스에 "acl_in" 또는 "acl_out"으로 이름을 적으세요.
- 경로는 라우터의 "routes"에 {"prefix": "네트워크/길이", "next_hop": "주소"}로 적으세요.
- 통신은 "flow"에 적으세요. ping은 "proto": "icmp", TCP는 "proto": "tcp"와 "dst_port".
- "id"는 "{synthetic-03}", "title"은 "{짧은 제목}", "source"는 "합성 사례(Workbench 초안, 정답은 사람이 적음)".
- "claim"은 지우고, "expect"는 {"result": ""}로 비워 두세요. 판정은 쓰지 마세요.
- JSON만 출력하세요. 설명은 쓰지 마세요.

[상황]
{아래 사례 하나의 [장비]·[설정]·[질문]을 그대로}

[형식 예시]
{synthetic-02 JSON}
```

**03 — ACL을 나가는 방향으로 붙임**

```text

- PC1: IP 10.10.10.10/24, 기본 게이트웨이 10.10.10.1
- R1(라우터): g0/0 10.10.10.1/24, g0/1 10.20.20.1/24
- SRV: IP 10.20.20.5/24, 기본 게이트웨이 10.20.20.1

[R1 설정]

access-list 110 permit ip any any

[질문]
PC1에서 SRV(10.20.20.5)의 SSH(TCP 22)에 접속할 수 있나요?
```

## 2. 같은 7개를 AI에 묻기

1번의 `expect`를 다 채운 **뒤에** 한다(정답을 먼저 정해 두어야 AI 답에 끌려가지 않는다).

- 프롬프트는 `docs/prompts/ai-claim-v1.md`의 A·B를 그대로 쓰고, `[장비]`~`[질문]`만 위 사례로 바꾼다. B는 `[가정]`을 **맨 앞**에.
- 로컬 Qwen으로 **A·B 각 1회**(7 × 2 = 14답). 생각 모드는 끔으로 고정하고 결과 파일에 적는다.
  v1은 3회였지만 CLCO·Qwen 모두 같은 질문에 거의 같은 문장을 냈다(2026-09-28). 1회로 줄인 이유를 결과 파일에 한 줄 남긴다.
- 답을 보낼 때 `Qwen · 03 · A · 1`처럼 붙인다.
- 채점은 v1과 같이 **판정 / 장비 / 단계**를 따로 센다.

## 3. Claude 제안에 반대 논거 받기

`disagreement-log.md`의 "결정을 기다리는 Claude 제안" 5가지를 정리한다. 찬성 논거는 이미 Claude에게 들었으니, Workbench에는 **반대만** 묻는다.

```text
나는 네트워크 실습용 판정 앱을 만들고 있습니다. 사용자가 라우터·ACL 설정과 통신(출발지, 목적지, 프로토콜, 포트)을 넣으면 "된다/안 된다"를 계산해 막힌 규칙을 보여 주는 앱입니다.
다른 AI가 아래 설계 결정 다섯 가지를 제안했습니다.

1. 앱 안에 LLM을 넣지 않는다. 판정은 규칙 계산으로만 한다.
2. 판정 결과는 네 가지다: 통과 / 거부 / 지원 범위 밖 / 입력 오류.
3. "통신된다"는 요청과 응답이 모두 오가는 것이다. ACL은 상태를 기억하지 않는다고 본다.
4. VLAN은 첫 버전에서 뺀다.
5. 서버는 Python으로 만든다(판정 엔진과 같은 언어).

각 결정마다 아래 두 가지만 한국어로 적어 주세요. 찬성 논거는 쓰지 마세요.
- 가장 강한 반대 논거 하나
- 이 결정이 틀렸다고 드러날 실제 상황 하나
```

받은 답을 보고 각각 **수용 / 일부 / 거절**과 근거를 `disagreement-log.md` 표에 적는다.
5번은 이미 FastAPI → Flask로 한 번 바꿨다(ADR-009). 그 결정도 같은 표에 적는다.

## 4. 동기 실습 설정 옮기기 (인터뷰 뒤)

동기가 설정과 실제 결과(ping·접속 화면)를 보여 주면 한다. **로컬 Qwen만 쓴다** — 설정이 PC 밖으로 나가지 않는다. CLCO가 외부 서비스인지는 아직 모른다.

```text
아래는 네트워크 실습 설정입니다. 두 가지를 해 주세요.
1. 사람 이름, 학번, 이름이 들어간 장비 이름(hostname), 비밀번호(enable secret, password 줄)를 지우고 PC1·R1·SRV 같은 이름으로 바꾸세요. IP 주소와 ACL·경로 설정은 한 글자도 바꾸지 마세요.
2. 결과를 아래 형식으로만 출력하세요. 설정에 없는 내용은 더하지 마세요.

[장비]
- 장비 이름: 인터페이스와 IP, (호스트면) 기본 게이트웨이
[라우터별 설정]
ACL과 경로, ip access-group 줄만

[원래 설정]
{동기 설정 붙여 넣기}
```

그다음은 1번과 같다(프롬프트 1로 JSON → `source`에 "동기 실습 사례(익명), 실제 결과: ○○ 캡처" → `expect`는 **실제 결과**로 채운다).
정답이 엔진이 아니라 실제 결과이므로, 여기서 pytest가 실패하면 엔진이 실제와 다르다는 뜻이다. 가장 값진 결과다.
