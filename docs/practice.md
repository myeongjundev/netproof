# 실습 과제 추가

`web/src/practice.ts`의 `PRACTICE`에 공개 예시(`/api/examples`)의 `id`와 같은 `case_id`, 제목, 한 줄 질문, 2~4개의 확인할 점을 추가합니다. 네트워크와 흐름은 예시 API에서 가져오므로 템플릿에 복사하지 않습니다. 대응하는 예시가 없으면 과제는 표시되지 않습니다.

질문과 확인할 점에 정답, 판정, 결정 규칙 번호를 쓰지 않습니다. 과제를 시작하면 받은 답은 비어 있으며, 사용자가 직접 판정하고 받은 답이나 자신의 예상을 적습니다. 기존 사례 파일의 `expect`와 손계산 기록은 변경하지 않습니다.

사례의 **복제해 다시 풀기**도 네트워크와 흐름만 편집 초안으로 가져옵니다. 원본은 바뀌지 않으며, 재판정 후 저장한 사례는 현재 사용자가 작성한 별개 사례입니다. 실제 결과와 검토자 확인은 새로 기록해야 합니다. 기존 **판정기에서 열기**는 받은 답까지 유지합니다.

전용 실습 화면은 현재 입력의 판정과 근거를 확인한 뒤 **⑤ 기록하기**에서 바로 사례를 저장할 수 있습니다. 로그인 후 제목을 적어 저장하면 서버가 같은 구성·통신·예상을 다시 계산해 기록하고 사례 상세로 이동합니다. 실제 결과는 상세에서 따로 적습니다. 저장 실패 시 입력은 유지되고, 저장 요청 중 편집하거나 화면을 떠났다면 늦은 응답이 상세로 이동시키지 않습니다. 로그인 왕복에서는 구성·예상만 남으므로 다시 판정해야 하며 새로고침하면 실습 입력이 사라집니다. ACL 점검·수정 후보에는 기존 **판정기로 가져가기**를 사용합니다.

과제 안내는 판정기 화면 안에서만 유지됩니다. 다른 화면으로 이동하면 안내는 사라지고 입력은 남습니다. 공유 링크와 사례 JSON에는 안내나 저장 제목이 포함되지 않습니다.

학습실의 **고치기 과제**는 합성 처음 구성과 목표 통신을 주고, 사용자가 구성을 바꿔 엔진 계산을 확인하는 세 문제입니다. 확인하기는 목표별 정책 검증과 처음 구성 대비 변경 영향을 함께 요청하고, 목표와 같음/다름·판정 불가 및 목표에 없는 통신의 변화를 표시합니다. 근거 보기는 선택한 목표의 구성도·경로 재생을 계산합니다. 채점하지 않으며 과제별 입력은 App 메모리에만 남아 화면 왕복에는 유지되고 새로고침에는 사라집니다. 서버·DB·URL·브라우저 저장소에 과제 입력을 기록하지 않습니다. 입력을 바꾸면 이전 결과로 표시하고 다시 확인해야 합니다. 모든 목표가 같고 비교한 목표 밖 변화가 없을 때도 검사한 서비스·호스트 쌍의 계산 사실만 말하며 검사하지 않은 통신이나 실제 장비 동작은 알 수 없습니다.
