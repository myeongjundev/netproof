# 학습 → 실습 → 기록·복습 흐름 강화 — 사용자 요구사항

작성: 2026-10-08. 상태: **사용자 방향 확정, Claude 설계 전**.

이 문서는 새 화면 설계나 구현 승인서가 아니다. 사용자가 선택한 방향과 현재 코드에서 확인한 연결을 설계 담당자가 이어받도록 기록한다.

## 사용자 요청과 참고 자료

- 사용자는 [정보처리기사 학습 플랫폼](https://information-processing-study.vercel.app/)을 영감의 출처로 제시하고, NetProof도 같은 방향으로 작업하자고 요청했다.
- 추가 질문에서 **「학습 → 실습 → 기록·복습 흐름을 강화」**를 선택했다. 홈과 메뉴를 참고 사이트처럼 재구성하는 선택지는 고르지 않았다.
- 참고 사이트의 공개 홈은 개념 익히기 → 문제로 확인하기 → 부족한 부분 복습하기 순서를 안내한다. 학습·기출문제 진입은 로그인 화면으로 이동했다. 내부 문제 풀이·오답노트·통계의 실제 동작은 확인하지 않았다.
- NetProof에 적용할 목적은 네트워크 개념을 이해하고, 자기 예상 또는 AI 답을 계산과 비교하고, 실제 결과를 기록해 사례를 다시 살펴보는 흐름을 쉽게 이어가는 것이다. 학습 효과나 사용자 성공률은 아직 측정하지 않았다.

코드만으로 확인한 저장 경계가 곧 사용성 결함이라는 뜻은 아니다. 기존 설계는 실습 화면에서 verify만 호출하고 저장은 판정기로 넘기도록 정했다. 사용자 요청에 맞게 이 경계를 유지할지 바꿀지는 Claude 설계와 사용자 승인으로 결정한다.

## 설계에서 충족해야 할 사용자 요구

1. 처음 온 사람이 개념을 살펴보고 실습을 시작할 수 있어야 한다. 이미 익숙한 사람의 직접 실습·판정기 진입도 고려한다.
2. 예상과 계산 근거를 비교한 뒤, 그 구성과 예상으로 사례 기록을 이어갈 방법이 분명해야 한다. 입력을 다시 작성하게 하거나 저장되지 않은 결과를 저장됐다고 안내하지 않는다.
3. 기록한 사례에 실제 결과와 출처를 추가하는 방법, 아직 실제 결과가 없는 상태를 구분해 안내한다.
4. 나중에 자기 예상과 계산이 달랐던 사례를 다시 찾아 근거를 보고, 새 예상으로 재실습하거나 필요한 개념을 다시 살펴볼 수 있어야 한다.
5. 로그인 전후·화면 이동·새로고침에서 무엇이 유지되는지 사용자가 알 수 있어야 한다. 영구 저장이나 개인 진도를 현재 기능처럼 약속하지 않는다.

## Claude가 정할 설계 항목

- 기존 실습 → 판정기 → 저장 경로를 어떻게 안내하거나 연결할지. 실습에서 직접 저장할지 여부와 변경 파일·API 범위는 아직 정하지 않았다.
- 사례를 관련 개념에 연결할 때 어떤 근거를 사용할지. 현재 사례에 학습 주제 연결을 위한 새 저장 필드가 필요할지, 기존 필드로 가능한지 확인한다.
- 기록·복습 진입을 기존 사례 필터와 상세에서 해결할지, 별도 화면이 필요한지. 「내 예상과 계산의 불일치」와 「계산과 실제 결과의 불일치」를 같은 의미로 다루지 않는다.
- 이번 과제에 넣을 최소 범위와 후속 범위. 단계마다 기존 동작·권한·입력 보존에 대한 실행 가능한 완료 조건을 쓴다.
- 설계는 HANDOFF의 목표·허용 파일·건드리지 않을 것·리스크·완료 조건으로 구체화하고 사용자 승인 뒤 Codex 구현으로 넘긴다.

## 유지할 저장소 원칙

- PASS/DENY와 비교 결과는 엔진·기존 API 응답을 사용한다. 화면에 판정·비교 로직을 복제하지 않는다.
- 사례 정답·expect는 사람이 정한다. 점수·정답 자동 생성·완료 판정은 이 사용자 요청에 포함되지 않았다.
- 합성 실습, 모델 계산, 실제 장비 관측, 검토자 확인을 구분한다. 실제 pfSense 검증과 D5는 별도 대기다.
- 로그인 없이 학습·실습·판정할 수 있는 접근과, 로그인/소유자/검토자 권한을 보존한다.
- 기존 실습·판정기 입력 분리와 명시적 가져가기·되돌리기는 설계에서 변경을 명시하기 전까지 유지한다.
- 기존 사례·API·화면 코드는 이번 요구사항 기록에서 변경하지 않는다. 참고 사이트의 본문·이미지를 복제하지 않는다.

## 설계 확인에 쓸 시나리오

아래는 이후 설계·구현 때 재현할 흐름이며 **이번에 실행해 통과한 결과가 아니다**.

- 비로그인 첫 방문 → 개념 → 실습 → 예상 선택 → 계산 근거 확인 → 기록 안내.
- 판정기에 기존 입력이 있는 상태 → 실습 편집 → 기록 단계 → 입력 보존·명시적 전환·되돌리기 확인.
- 로그인 전후 같은 구성·예상을 보존해 사례 저장 → 상세에서 저장 내용을 확인.
- 저장된 자기 사례 → 실제 결과·출처 기록 → 내 사례·불일치 조건으로 다시 찾기 → 새 예상으로 다시 확인.
- 실제 결과 미정, 예상 없음, UNSUPPORTED/INVALID, API 오류·지연, 화면 이동·새로고침의 상태 구분.
- 375px·1280px, 키보드 이동과 기존 주소 호환. 수동 QA A~E는 사람이 별도로 기록한다.
