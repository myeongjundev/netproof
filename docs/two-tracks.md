# NetProof 두 트랙 범위 결정 (2026-10-01)

사용자 확인: 초기에는 Cisco ACL을 썼지만 지금 실습에서는 사용하지 않는다. 현재 사용하는 도구는 Cloudflare, Graylog, Wazuh, n8n, Kali Linux다. 사용자는 기존 ACL 학습과 현재 실습을 **두 트랙으로 분리**하기로 결정했다(ADR-016).

| 트랙 | 목적과 현재 상태 | 판정·증거 경계 |
|---|---|---|
| A. ACL·라우팅 학습 | 현재 구현된 NetProof. 구조화한 네트워크와 무상태 ACL의 흐름을 계산한다. `engine/`, `docs/semantics.md`, 합성 사례, 이슈 #9가 여기에 속한다. | `PASS`·`DENY`는 **입력된 모델 안에서만** 의미가 있다. Cloudflare나 Wazuh의 실제 차단·탐지 결과라고 표시하지 않는다. |
| B. 현재 실습 증거 | 새 범위. 사용자가 허가된 실습에서 얻은 Kali 실행 결과, Cloudflare·Wazuh·Graylog의 설정·이벤트, n8n 실행 기록을 한 사건의 시간순 증거로 연결하는 흐름을 설계한다. 아직 구현·연동되지 않았다. | 어떤 제어가 요청을 막았는지, 어떤 탐지가 발생했는지는 해당 제품의 설정과 관측 기록으로 확인한다. 로그가 없다는 사실만으로 허용·차단을 단정하지 않는다. 기존 ACL 엔진의 판정을 재사용하지 않는다. |

두 트랙은 사례의 **질문, 입력 출처, 결과 근거**를 구분한다. A의 합성 ACL 사례를 B의 실습 검증 수치에 섞지 않는다. B에는 현재 `PASS`·`DENY` 판정 의미론이 없으며, 새 판정이 필요하면 ADR-001에 맞는 결정적 규칙과 사람이 확인한 실제 결과를 먼저 정의한다. 앱 안 LLM 판정은 넣지 않는다(ADR-002). 비밀값, 세션, 원본 로그의 민감 정보는 공개 저장소에 넣지 않는다.

## 다음 작업의 순서

1. A의 공개 `/api/verify` 예외인 이슈 #9와 계약 테스트·CI는 기존 작업 정의대로 마무리한다. A를 현재 실습 전체의 정확도 지표로 홍보하지 않는다.
2. B의 첫 사례 **하나**를 고른다. 허가된 대상, 기대한 제어/탐지, Kali에서 보낸 요청 또는 관찰, 각 도구에서 얻을 수 있는 증거와 시각, 최종 확인자를 기록한다. 사용자가 제공한 도구 이름만으로 Cloudflare의 특정 제품이나 로그 형식을 추정하지 않는다.
3. 그 사례를 바탕으로 B의 최소 데이터 형식·근거 규칙·공개 범위를 별도 설계한다. 계정 연결, 자동 수집, n8n 자동화와 새 판정 API는 설계 후에 결정한다.
4. 현재 `HANDOFF.md`의 Cisco 설정 붙여넣기 및 ACL 중심 기능 확대는 A의 선택 작업으로 재분류한다. B의 첫 사례를 대체하지 않는다.

`plan.md`와 `HANDOFF.md`의 이전 Cisco·ACL 일정은 A를 위해 남긴 역사적 계획이다. B의 성공 조건과 일정은 첫 실제 사례가 확보된 뒤 정한다.
