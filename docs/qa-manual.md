# 사용자 수동 QA 체크리스트

사람이 위에서부터 직접 확인하고 표시합니다. 합성 계정·사례는 화면 확인용이며 실제 장비 관측이나 정답이 아닙니다.

## 준비

- [ ] 저장소 루트에서 `npm --prefix web run build`
- [ ] `.venv/Scripts/python scripts/qa_local.py` 실행 (다른 포트: `--port 4861`)
- [ ] 콘솔 주소 `http://127.0.0.1:4860/` 접속. 콘솔의 `qa_author`로 로그인하고 필요하면 `qa_reviewer`로 전환
- [ ] 375×812·1280×800, 라이트(기본)·다크(설정 › 화면)에서 아래 항목 확인

도구는 DATABASE_URL을 무시하고 새 OS 임시 SQLite만 씁니다. 비밀번호는 매번 바뀌며 콘솔에만 나옵니다. 비밀번호·쿠키·토큰을 캡처하거나 기록하지 마세요. **강제 종료하면 임시 폴더가 남을 수 있으니 Ctrl+C로 끕니다.** 정상 종료하면 임시 폴더를 삭제합니다.

## A. PR #20 G2 화면 확인

- [ ] 사례 게시판 목록: 휴대폰 필터 접기·펼치기, 적용 조건 표시, 검색, 초기화
- [ ] 네 합성 사례(받은 답 없음·AI 답·내 예상·긴 제목)가 보이고 화면 밖으로 넘치지 않음
- [ ] 사례 상세: 구성 원문, 받은 답, NetProof 계산이 서로 구분됨
- [ ] 휴대폰 사례 상세: 구성 요약을 접었을 때 `받은 답` 제목이 첫 화면 안에 보임. 펼치면 장비·ACL 원문이 보이고 ACL별 접기도 유지됨. 1280에서는 요약 줄 없이 기존 구성이 보임

## B. 삭제 취소 — 실제 브라우저 기본 확인창

- [ ] `qa_author`로 합성 사례 상세에서 삭제를 누르고 **실제 기본 확인창의 취소**를 직접 누름
- [ ] 취소 뒤 같은 주소에 머묾
- [ ] 새로고침 뒤에도 사례가 남음
- [ ] 가능하면 개발자 도구 Network에서 DELETE 요청이 없음을 확인 (못 보면 미확인으로 기록)

confirm을 대체하거나 우회한 검사는 이 항목의 근거가 아닙니다.

## C. 홈·전용 실습 흐름

- [ ] 판정기에 입력을 써 둔 채 홈에서 `막힐 것 같다` → 전용 실습 화면이 바로 열리고 ③ 내 예상에 선택이 반영됨. 판정기로 돌아가면 기존 입력이 그대로임
- [ ] 문제 → 구성 → 내 예상 → 판정하기 → 판정과 근거의 순서, 학습 상세의 질문·`이 실습에서 볼 것:` 부제 확인
- [ ] 휴대폰 흉내(화면 폭과 내용 폭이 같고 스크롤바가 겹침) 360×800·375×812의 실습 01·02·03: 안내를 닫고 ② 구성을 접으면 ③ 제목·세 라디오·`예상은 계산에 쓰지 않고 비교만 합니다.` 문장이 고정 판정 줄 위에 보임. ③ 칸 아래 테두리까지 보이는 기준은 360×812·375×812임. 구성 요약 → 펼치기 → 편집 → 다시 판정, `입력에서 보기`로 접기가 먼저 열리고 ACL 줄이 선택됨. 1280에서는 요약 줄 없이 기존 배치가 유지됨
- [ ] 판정 → 내 예상과 NetProof 계산의 비교 배너 문장 확인. 1280×800에서 안내를 닫으면 결과 제목·배너가 스크롤 없이 보이고, 휴대폰에서는 결과 제목으로 포커스·스크롤이 옮겨짐
- [ ] ACL 편집 → 이전 결과 표시 → 다시 판정. `처음 상태로`는 예상을 유지하며, 되돌리기로 편집 내용이 복구됨
- [ ] 판정기·실습 01에서 판정 → 1번 deny를 같은 서브넷 전체 deny ip로 바꿈 → 다시 판정 → 변경 전/후 막힘·다른 통신 영향 새로 막힘 9개(SRV→PC1 포함). 그 줄 삭제 → 다시 판정 → 변경 전 막힘/후 통과·새로 열림 9개. 받은 답만 변경 시 기준 유지, 포트 변경·불러오기 시 기준 없음, 편집 중 이전 입력 안내·영향 단추 막힘 확인
- [ ] `입력에서 보기` → 해당 ACL 줄이 ② 구성에서 선택됨
- [ ] 판정기에 입력이 있을 때 `판정기로 가져가기` → 알림 → 되돌리기로 원래 판정기 입력 복구. 손대지 않은 빈 판정기에서는 알림 없이 구성만 들어옴. 판정기에는 실습 안내 패널이 없음
- [ ] 홈의 `하던 실습이 있어요`·`실습 이어서 하기`·다음 실습 확인
- [ ] 첫 방문 안내 → `알겠어요` → 새로고침 후 안내가 다시 나오지 않음

- [ ] 로그인한 360×800·375×812에서 헤더 높이 68px·한 줄, 실습01·02·03의 ③ 위치가 위 기준과 같음. 20자 닉네임 말줄임·가로 넘침 0, 역할은 설정 화면에서 확인. 1280 헤더는 기존과 같음

## D. 보안 로그 — 수업 환경 수동 확인

**사용자 확인 대기. AI의 로컬 파일·UDP 검사는 실제 Graylog·Wazuh 수집 완료가 아닙니다.**

- [ ] [보안 로그 연결 문서](security-logs.md)의 설정 순서대로 로컬 QA·합성 계정만 준비한다. 비밀번호·쿠키·토큰·없는 닉네임 입력 문자열을 기록하지 않는다
- [ ] Graylog Syslog UDP 입력·파이프라인·스트림 연결 후 login_failure와 account_locked가 검색되고 필드로 나뉜다
- [ ] 같은 주소의 2분 동안 실패 5번 이벤트 정의·알림이 수업 환경에서 동작한다
- [ ] Wazuh 에이전트가 JSONL을 수집한다. wazuh-logtest로 JSON 디코딩과 100200 규칙을 먼저 확인한다(syslog 직접 수신은 선택)
- [ ] Wazuh 대시보드에 실패(100200/5)·잠금(100201/10)·반복(100202)·설정 확인 실패(100203/5)가 구분돼 보인다
- [ ] 학습실 Graylog·Wazuh 주제의 공식 출처·문서 기준을 확인하고, 로그에 비밀번호/없는 닉네임이 없음을 확인한다
- [ ] 종료는 Ctrl+C로 하고 환경 변수를 해제한다. 실제 수집·검색·경보의 통과/문제/미확인은 사람이 아래에 기록한다
