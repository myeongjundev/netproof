# AI 답 받기 프롬프트 v1

NetProof 사례마다 AI(로컬 Qwen, 수업용 CLCO 등)에게 "이 통신이 되나?"를 물어, 그 답을 NetProof의 **받은 답(AI)**으로 기록한다.
목적은 "AI가 어떤 유형에서 틀리는가"를 모으는 것이다. 정답은 NetProof 계산이 아니라 **실습망 결과**다.

## 설계에서 정한 것

| 결정 | 이유 |
|---|---|
| 정답이나 NetProof 결과를 프롬프트에 넣지 않는다 | 답을 흘리면 AI를 시험하는 게 아니다 |
| A(동기처럼 묻기)와 B(가정을 적어 묻기) 두 가지 | "가정을 밝혀 주면 AI가 덜 틀리나"를 따로 잴 수 있다 |
| 답 형식을 네 줄로 고정 | 기록을 빠르게 옮기고 모델끼리 비교하려고 |
| "판단할 수 없다"를 고를 수 있게 | 모르는 걸 모른다고 하는지도 본다(NetProof의 UNSUPPORTED에 해당) |
| 질문마다 **새 대화**, 같은 질문 **3번** | 앞 대화가 섞이지 않게. Qwen은 기본 temperature가 1이라 같은 질문에도 답이 바뀔 수 있다 |
| 한국어로만 답하라고 적는다 | 이 모델은 한국어 답에 중국어가 섞이는 버릇이 있다(2026-09-28 확인) |

## 프롬프트 A — 동기처럼 묻기

`{ }` 부분만 사례에 맞게 바꾼다. 아래는 `cases/synthetic-01`을 채운 예.

```text
아래는 네트워크 실습 구성입니다. 질문에 답해 주세요.

[장비]
- PC1: IP 10.10.10.10/24, 기본 게이트웨이 10.10.10.1
- R1(라우터): g0/0 10.10.10.1/24, g0/1 10.20.20.1/24
- SRV: IP 10.20.20.5/24, 기본 게이트웨이 10.20.20.1

[R1 설정]
access-list 101 deny tcp 10.10.10.0 0.0.0.255 10.20.20.0 0.0.0.255 eq 443
access-list 101 permit ip any any
interface g0/0
 ip access-group 101 in

[질문]
PC1에서 SRV(10.20.20.5)의 HTTPS(TCP 443)에 접속할 수 있나요?

[답하는 형식]
아래 네 줄로만, 한국어로 답하세요. 다른 언어를 섞지 마세요.
판정: 된다 / 안 된다 / 판단할 수 없다 중 하나
막히는 곳: 장비 이름, 인터페이스, 방향(들어올 때/나갈 때). 된다면 "없음"
근거: 판정을 가른 설정 한 줄을 그대로 옮기기. 없으면 "없음"
이유: 두 문장 이내
```

## 프롬프트 B — 가정을 적어 묻기

A의 `[질문]` 바로 앞에 이 블록만 더한다. 나머지는 A와 같다.

```text
[가정]
- 같은 서브넷에 있는 인터페이스끼리는 직접 연결돼 있습니다.
- ACL은 상태를 기억하지 않습니다. 응답 패킷도 ACL을 따로 통과해야 합니다.
- "접속할 수 있다"는 요청과 응답이 모두 오간다는 뜻입니다.
- 설정에 적히지 않은 경로나 규칙은 없는 것으로 봅니다.
```

## 다른 사례 예 — `cases/synthetic-02`(ping, 경로 문제)

```text
[장비]
- PC1: IP 10.10.10.10/24, 기본 게이트웨이 10.10.10.1
- R1(라우터): g0/0 10.10.10.1/24, s0/0 192.168.12.1/30
- R2(라우터): s0/0 192.168.12.2/30, g0/0 10.30.30.1/24
- SRV2: IP 10.30.30.5/24, 기본 게이트웨이 10.30.30.1

[R1 설정]
ip route 10.30.30.0 255.255.255.0 192.168.12.2

[R2 설정]
(정적 경로 없음)

[질문]
PC1에서 SRV2(10.30.30.5)로 ping이 되나요?
```

## 하는 순서

1. Workbench에서 **새 대화**를 열고 모델을 고른다(로컬 Qwen 또는 CLCO). 생각 모드가 켜져 있는지 적어 둔다.
2. 프롬프트 A를 붙여 넣는다. 같은 질문을 **새 대화에서 3번** 반복한다.
3. 같은 사례로 프롬프트 B도 3번.
4. 같은 과정을 CLCO로도 한다(모델별로 따로 센다).
5. NetProof에서 사례를 열고 **받은 답**에 기록한다.
   - 판정 "된다" → PASS, "안 된다" → DENY, "판단할 수 없다" → "비교 안 함"으로 두고 메모에 적는다
   - 답의 종류: AI의 답
   - 누구의 답인가: `qwen3.5:9b · 로컬 · 생각 켬 · 프롬프트 A-v1 · 2026-09-28 · 3회 중 2회`
   - 답 원문: 네 줄 그대로
6. NetProof 판정과 AI 답이 다르면, 실습망 결과(ping·Nmap·접속)로 누가 맞는지 확인한다.

## 지킬 것

- **답을 보고 프롬프트를 고치지 않는다.** 고치고 싶으면 v2로 새 파일을 만들고 바꾼 이유를 적는다. 답을 본 뒤 몰래 고치면 AI를 시험한 게 아니라 정답으로 유도한 것이 된다.
- 3번 답이 서로 다르면 그것도 결과다. 몇 번 중 몇 번이었는지 적는다.
- 동기 실습 설정을 쓸 때는 이름·학번 같은 개인 정보를 지우고 넣는다. 로컬 Qwen은 PC 밖으로 보내지 않지만, CLCO는 외부 서비스일 수 있다(확인 필요).
- 발표에서 "AI가 틀렸다"를 말할 때는 **모델 이름·크기·조건**을 함께 밝힌다. 9B 로컬 모델의 오답률을 "AI 전체"로 일반화하지 않는다.
