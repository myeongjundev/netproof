# NetProof 홈·학습실·헤더 MVP 승인 설계

상태: **2026-10-04 사용자 승인 — “작업진행하자”**

작성: 2026-10-04. 사용자 요청으로 이번 설계만 Codex가 맡는다. 저장소의 일반 역할 규칙을 영구 변경하지 않는다. 리뷰와 병합은 별도 단계다.

## 설계의 중심

홈은 기능을 늘어놓는 대시보드가 아니라 **처음 온 사람의 시작점과 다시 온 사람의 돌아갈 길**이다.

첫 방문: 홈 → 학습실에서 질문과 확인할 개념을 읽기 → 판정기에서 구성 불러오기 → 예상 입력 → 계산 근거 확인.

작성 중 방문: 홈 → 현재 입력으로 돌아가기. 이 단계에서는 새로고침 복구를 약속하지 않는다.

현재 구현에서 확인한 제약:

- `App.tsx`의 Draft는 메모리에만 있으며 화면 이동 중 유지된다. 자동 저장은 없다.
- 판정 결과·실습 선택·되돌리기는 JudgePage 내부 상태다. 화면을 떠났다가 돌아오면 결과가 유지된다고 안내하지 않는다.
- 사례 게시판과 상세는 로그인 전용이다. 홈은 사례 원문·제목·닉네임을 비로그인 사용자에게 노출하지 않는다.
- 기존 판정기 `#/`, 공유 `#/s/<payload>`, 정책 검증 `#/matrix`, 사례·설정·대시보드 주소를 보존해야 한다.
- 합성 실습은 이미 3개다. 신규 정답·채점·사례 파일을 만들 필요가 없다.
- 현재 앱 코드가 origin/main과 같은지 읽기 비교했다. 작업 worktree HEAD `f7d795d`, origin/main `b3f145b`. HANDOFF의 PR #22 대기 문구는 이전 기록이며 이번 초안으로 덮어쓰지 않았다.

## 1) 이번 구현 범위와 하지 않는 일

1차 MVP에 넣는다:

- 공개 홈과 고정 메인 배너 1장.
- 공개 학습실: 기존 3개 합성 실습의 주제·질문·체크포인트·지원 범위 안내.
- 홈/학습실로 이동하는 헤더, 휴대폰 메뉴 접기.
- 메모리에 현재 입력이 있으면 홈에 돌아가기 안내.
- 기존 실습 불러오기·되돌리기 동작을 이용한 안전한 학습실 → 판정기 연결.
- 로그인 필요 여부와 계산/관측 구분 안내.

다음 단계로 분리한다:

- **내 실습**: 초안 영구 저장·최근 기록·북마크·비공개 저장. 실제 기능을 만들기 전에는 헤더에 빈 메뉴를 넣지 않는다.
- 자동 저장, 브라우저 저장소, 공용 PC 저장 끄기/지우기, 다중 탭 충돌 처리.
- 개인 진도율·점수·스트릭·랭킹·정처기 문제은행·학습 분석 수집.
- 홈의 실제 사례 피드·추천 알고리즘·새 공지 관리 API·관리자 배너 편집.
- 보안 뉴스/KEV 수집, 외부 사이트 본문·이미지 복제, 앱 안 LLM 호출.
- 엔진·서버·DB·API 계약·expect 변경, 배포·병합.
- 기존 F5·F6, PR #20 G2·실제 삭제 취소 수동 QA. 이번 설계로 해결 처리하지 않는다.

## 2) 정보 구조와 주소 호환

최종 확장 방향: `NetProof(홈) | 학습실 · 판정기 · 정책 검증 · 사례 게시판 · 내 실습 | 계정`.

**이번 헤더:** `NetProof(홈) | 학습실 · 판정기 · 정책 검증 · 사례 게시판 | 설정 · 로그인/기존 사용자 표시`.

- 로고가 홈 링크다. 별도 ‘메인’ 탭을 중복 추가하지 않는다. 홈일 때 로고에 `aria-current="page"`.
- 기존 검토자 대시보드는 검토자에게만 보이도록 유지한다. 숨김이 권한 검사를 대신하지 않는다.
- 설정은 보조 위치로 이동하되 계속 접근 가능하다. 새 계정 드롭다운은 이번에 만들지 않는다.
- 사례 게시판은 메뉴에 계속 보인다. 로그인하지 않은 경우 기존 로그인 안내를 이용한다.

| 진입 주소 | 화면 | 처리 |
|---|---|---|
| 해시 없는 최초 주소, 빈 해시 `#` | 홈 | 새 기본 진입점 |
| `#/home` | 홈 | 로고와 명시적인 홈 링크 |
| `#/` | 기존 판정기 | 기존 링크·사례 열기·공유 해제 후 주소 보존 |
| `#/learn` | 학습실 목록 | 3개 주제와 선택 안내 |
| `#/learn/https-acl` | 학습실, HTTPS·입력 ACL 상세 | 선택된 주제 설명 |
| `#/learn/round-trip` | 학습실, 왕복 경로 상세 | 선택된 주제 설명 |
| `#/learn/output-acl` | 학습실, 출력 ACL 상세 | 선택된 주제 설명 |
| `#/practice/synthetic-01`, `02`, `03` | 판정기 + 선택 실습 안내 | **주소 진입만으로 입력을 바꾸지 않음** |
| `#/s/<payload>` | 기존 공유 판정기 | 홈으로 우회하지 않고 공유 해독 동작 유지 |
| 기존 matrix/cases/login/settings/dashboard | 기존 화면 | 접근·로그인 복귀·권한 유지 |

알 수 없는 학습/실습 ID는 ‘없는 화면’이다. 임의 예시를 대신 불러오거나 조용히 첫 과제로 바꾸지 않는다. 쿼리 문자열은 기존 사례 목록 규칙만 유지한다.

빈 해시의 기본 화면 변경은 제품 변경이므로 사용자 승인 대상이다. 기존 `#/`를 홈으로 바꾸지 않는 이유는 앱 안팎의 판정기 링크를 일괄 변경할 필요가 없기 때문이다.

로그인 후 원래 목적지로 돌아가는 기존 동작은 유지한다. 홈에서 로그인한 경우 홈으로 돌아온다. 로그아웃 목적지는 명시적 `#/home`으로 설정한다. 로그아웃 성공 시 현재 Draft 처리 정책은 기존과 동일하며 자동 저장·게시판 등록을 추가하지 않는다.

## 3) 홈 배치·문구·상태

순서: 헤더 → 고정 배너 → 조건부 현재 입력 안내 → 주제 카드 3개 → 사례 게시판 안내 → 지원 범위/푸터.

### 메인 배너

- 작은 라벨: `네트워크 설정 검증 실습실`.
- 제목: **왜 통과하고, 어디서 막힐까요?**
- 설명: `내 예상이나 받은 답을 NetProof 계산과 비교하고, 경로와 ACL 근거를 직접 살펴보세요.`
- 주요 버튼: `첫 실습 둘러보기` → `#/learn/https-acl`. 입력 변경 없음.
- 보조 링크: `판정기로 이동` → `#/`. 입력 초기화 없음.
- 바로 아래: `모델 안의 계산입니다. 실제 장비 결과는 별도로 확인합니다.`
- 데스크톱 오른쪽에는 `입력 → 계산 근거 → 실제 결과 확인`이라는 안내 도식만 둔다. 통과/막힘, 정확도·성공률, 회원 수, 실습 시간 같은 가짜 데이터를 만들지 않는다.
- 광고처럼 순환하는 슬라이드·자동 재생·큰 외부 사진·과도한 애니메이션 없음. 새 공지가 없으면 공지 띠도 없음.

### 현재 입력 안내

- App 메모리 Draft의 직렬화 스냅샷이 새 `blankDraft()`의 스냅샷과 다를 때만 표시한다. 이것은 **초기 템플릿과의 표시 비교**이지 입력 유효성/판정 검사 아니다.
- 제목: `작성 중인 입력이 있습니다`.
- 설명: `이 페이지를 떠나기 전의 입력으로 돌아갈 수 있어요. 새로고침하면 입력은 사라집니다.`
- 버튼: `현재 입력으로 돌아가기` → `#/`. Draft를 바꾸지 않는다.
- 저장 시간·마지막 판정·학습 진도·완료 여부는 표시하지 않는다. 이전 판정 결과는 복원하지 않는다.
- 초기 템플릿, 새로고침 직후, 사용자 입력이 초기 템플릿과 동일하면 표시 없음.

### 주제 카드

| 표시 제목 | 질문 | 기존 실습 ID | 상세 주소 |
|---|---|---|---|
| HTTPS와 입력 ACL | PC1에서 SRV의 HTTPS에 접속할 수 있나요? | synthetic-01 | /learn/https-acl |
| 왕복 경로 | PC1에서 SRV로 보낸 통신이 왕복할 수 있나요? | synthetic-02 | /learn/round-trip |
| 출력 ACL | 나가는 패킷에 ACL은 어떻게 적용되나요? | synthetic-03 | /learn/output-acl |

카드에는 제목·짧은 질문·`살펴보기` 링크만. 실습을 켰다는 이유로 ‘완료’, ‘통과’, ‘숙련’ 배지를 만들지 않는다. 전부 **합성 실습**임을 섹션에 명시한다. 예시 파일명이나 expect를 읽어 정답을 카드에 노출하지 않는다.

### 사례 게시판 안내

첫 단계는 실제 사례 카드가 아닌 안내 1개다.

- 제목: `계산 근거와 실제 결과를 함께 살펴보세요`.
- 비로그인: `사례 게시판은 로그인한 동기끼리 봅니다.` / `사례 게시판으로` → 기존 로그인 필요 안내 → 로그인 → 원래 게시판.
- 로그인: `동기들이 기록한 구성과 계산 근거, 실제 결과 확인 상태를 살펴보세요.` / 같은 게시판 링크.
- 홈은 `/api/cases`·대시보드·검토 집계를 조회하지 않는다. 사용자 이름·사례 제목·출처·원문을 미리 싣지 않는다.
- ‘추천’·‘검증 완료’·‘신뢰도 높은 사례’라고 부르지 않는다. 편집자 선정과 실제 확인 기준이 아직 없기 때문이다.

## 4) 학습실과 안전한 실습 연결

학습실의 역할은 **개념 안내와 기존 실습 선택**이다. 별도 계산기나 채점기가 아니다.

세 주제를 목록으로 보여 주고 상세를 선택한다. 상세 순서:

1. 질문 — 정답이나 막히는 원인을 미리 공개하지 않는다.
2. 개념 — 해당 주제에 필요한 기본 개념을 2~3문장으로 고정 작성.
3. 쉬운 비유 — 보조 설명 1문장. 비유를 실제 모델 의미보다 앞세우지 않는다.
4. 확인할 것 — 기존 PRACTICE.checkpoints를 그대로 연결.
5. `판정기에서 실습 살펴보기` → 대응 `/practice/synthetic-0N`.
6. 출처와 한계 — `NetProof 모델 의미론 · 합성 실습`. 주제별 docs/semantics.md 해당 절을 저장소 링크로 제공한다.

내용의 기준은 repository `docs/semantics.md`: HTTPS·입력 ACL은 5·6절, 왕복 경로는 2·4·5절, 출력 ACL은 5·6절. 모든 상세에 `계산 결과는 실제 장비 동작을 보장하지 않습니다.`를 짧게 넣는다. 연속 wildcard·established·무상태와 상태 기반 방화벽을 혼동하지 않는다. 외부 자료를 새로 인용한다면 원문 확인과 직접 출처 링크가 필요하며 무단 복제를 하지 않는다.

데이터는 신규 `learning.ts`의 고정 lesson 메타데이터와 기존 PRACTICE를 case_id로 연결한다. 체크포인트·정답을 서로 다른 화면에 복제하지 않는다. 기술 설명은 리뷰 대상이며 claim·result·expect·채점 함수를 데이터에 넣지 않는다.

### 판정기에 들어왔을 때

- 새 practice 경로는 기존 JudgePage다. 선택한 질문과 **‘실습 구성 불러오기’** 버튼을 보여 준다.
- 진입·새로고침·앞/뒤로 가기·API 완료만으로 기존 Draft를 덮어쓰지 않는다.
- 버튼을 **직접 누른 때에만** 기존 실습 시작 경로를 이용한다: `fromCase(example)`에 EMPTY_CLAIM을 넣고 기존 load/undo/revision 처리를 거쳐 task를 설정한다. 기대값·정답을 가져오지 않는다.
- 현재 입력이 바뀌는 경우 기존 한 단계 되돌리기 알림이 동작한다. 직접 편집 시 알림이 닫히는 규칙 유지. 공유 링크 첫 진입 규칙도 그대로.
- 이 추가 연결만을 위한 공통 startPractice 경로를 추출할 수 있지만 기존 실습 버튼의 동작을 바꾸지 않는다. F5/F6를 함께 고치지 않는다.
- 불러오기 후 선택 URL을 `#/`로 history.replaceState하여 뒤로가기는 학습실로 돌아간다. 해당 선택을 주소 진입으로 다시 실행하지 않는다.
- 예시 API 조회 중: 버튼 비활성 + `실습 구성을 불러오는 중…`.
- API 실패: `실습 구성을 가져오지 못했습니다.` + `다시 시도` + 입력을 유지하는 `판정기로 이동` 링크. 다른 예시로 대체하지 않는다.
- 성공 응답에 해당 ID가 없으면 `이 실습 구성은 현재 제공되지 않습니다.`. 구성 불러오기 버튼 없음; 판정기로 이동 가능. 실패와 자료 없음은 구분한다.
- 늦은 응답은 선택한 ID/현재 페이지와 다르면 무시한다. 홈 방문만으로 verify·audit·suggest·case 저장을 호출하지 않는다.

## 5) 화면 규격과 접근성

- 기존 Pretendard, 녹색 계열 accent, light-dark 토큰을 사용한다. 판정 배너의 PASS/DENY 색과 홈 장식색을 혼동하지 않는다.
- 홈 최대 폭 1200px 안팎, 기존 main 1280px 안에서 배치. 여백 desktop 24px, mobile 16px.
- 배너는 desktop에서 설명/안내 도식 2열, 카드 3열. 960px 이하 헤더 메뉴 접기. 720px 이하 배너·카드·학습 상세 모두 1열.
- 375px에서는 제목 28~32px, 본문 15~16px, 주요 버튼 폭 충분히 확보. 1280px 제목 36~44px. 카드 문장을 축약 부호로 자르지 않는다.
- 헤더는 일반 문서 흐름. 새 고정 하단 메뉴나 sticky 배너를 추가하지 않아 기존 모바일 판정 버튼과 겹치지 않는다.
- 모바일 메뉴는 ‘메뉴’ 버튼 + 본문 흐름 안의 펼침 영역. `aria-expanded`/`aria-controls`, Escape 닫기 후 버튼 focus 복귀, 목적지 선택 시 닫기. 모달·focus trap 아님.
- 한 화면에 h1 하나, 의미 있는 h2, 실제 링크는 a, 동작은 button. 장식 도식은 aria-hidden 또는 간단한 대체 설명.
- 텍스트 대비 4.5:1, 터치 대상 약 44px, visible focus. 색만으로 현재 탭·상태를 전달하지 않는다.
- 로그인 확인 중에도 홈·학습 설명·판정기 이동은 사용할 수 있다. 로그인 여부만 미확정 표시하고 전체 홈을 ‘확인 중’으로 막지 않는다.
- 200% 확대와 320px 폭도 점검. 가로 스크롤·카드 내부 스크롤 없음. 라이트/다크 모두 지원.
