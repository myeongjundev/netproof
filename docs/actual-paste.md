# 실제 결과 출력 붙여넣기

사례 작성자는 상세 화면의 실제 결과 패널에서 **출력 붙여넣기 → 후보 만들기 → 입력칸에 적용 → 실제 결과 저장**을 차례로 누른다. 후보 만들기와 적용만으로는 저장되지 않는다. 미정 후보를 적용해도 기존 결과 선택은 유지하며 출처와 메모 요약만 반영한다. 기존 메모 뒤에 요약을 덧붙여 코드포인트 1000자까지 남긴다.

영어·한국어 Windows ping과 Linux ping의 단일 IPv4 머리글·통계·패킷 수·손실률, Nmap 일반 텍스트의 단일 IPv4 대상·TCP/UDP 포트 한 줄을 지원한다. 흐름은 ICMP echo 또는 해당 목적지 포트여야 한다. 여러 대상/포트, 목적지 불일치, 혼합/잘린 출력, 제어문자, ASCII가 아닌 숫자, 4000자·80줄 초과를 거절한다. Cisco·traceroute·curl·XML·grepable 형식·호스트 이름만 있는 출력은 지원하지 않는다. 출력의 모든 IPv4는 사례 목적지와 같아야 하므로 중간 장비 오류 응답도 자동 적용하지 않는다.

원문 전체는 저장하거나 로그에 기록하지 않는다. textarea 지역 상태는 화면을 떠나면 사라진다. 사용자가 확인해 저장하는 메모에는 머리글/통계 또는 대상/포트 근거 최대 2줄(각 120자)만 포함된다. 장비 이름·주소가 포함될 수 있으므로 필요한 줄만 붙여넣고 메모도 확인한다. 원문을 위조했는지나 실제 출발지를 파서가 증명할 수 없다.

지원 형식을 넓힐 때는 엔진 `observe.py`의 인식·거절 규칙과 `test_observe.py`에 합성 출력 회귀를 함께 추가하고 [판정 의미 9절](semantics.md)의 매핑 표를 검토한다. 서버와 화면에 결과 매핑을 복제하지 않는다. 기존 `cases/*.json`의 사람이 정한 기대값은 바꾸지 않는다.

참조: [Microsoft ping 설명](https://learn.microsoft.com/windows-server/administration/windows-commands/ping), [Nmap 포트 상태](https://nmap.org/book/man-port-scanning-basics.html). 실제 장비에서 명령을 실행하거나 패킷을 보내는 기능은 포함하지 않는다.
